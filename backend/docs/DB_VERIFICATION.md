# Перевірка на справжньому PostgreSQL (01.11.2026)

Уперше міграції, сид, інтеграційні тести і живий сценарій користувача пройшли проти справжньої бази. PostgreSQL 17.11 (офіційні бінарні файли EnterpriseDB для Windows) запускався локально на `127.0.0.1:54329` у тимчасовій теці, без встановлення в систему.

## Живий сценарій (зібраний `dist/main.js` на базі із сидом)

- Гість: тариф паркінгу з рядками для екрана, розрахунок за 80 хв = 60 ₴, інформація про ТРЦ з адресою «просп. Соборності, 43, Луцьк», акції, винагороди й орендарі без входу.
- Вхід за OTP (dev-ехо коду), картка клубу з QR `PC1:734211800:…` і підсумком чеків на модерації.
- Паркінг: стан F3 «До сплати 60 ₴», дії «Оплатити» і «Я вже виїхав», «оновлено HH:MM».
- Сканування QR чека на 450 ₴: «Чек зараховано», +13 балів з утриманням 24 год (новий акаунт).
- Той самий чек з нулями перед номером: 409 `PC_RECEIPT_DUPLICATE` (захист від повторного зарахування працює).
- Обмін 40 балів на «Година паркінгу»: ваучер видано.
- У лозі запитів `authorization` та `idempotency-key` замасковано; помилок немає.

## Що ця перевірка знайшла і що виправлено

1. **Міграції лежали не там, де їх шукає Prisma.** Зі схемою в теці `prisma/schema` Prisma 6 шукає міграції поруч, у `prisma/schema/migrations`. З `prisma/migrations` команда `migrate deploy` повідомляла «No pending migrations» і не застосовувала нічого: CI і контейнер працювали б на порожній базі. Теку перенесено, усі посилання оновлено.
2. **Номер звернення в підтримку.** Власна послідовність через `dbgenerated(nextval(...))` давала постійний дрейф, і `prisma migrate dev` пропонував би її видалити. Поле стало `@default(autoincrement())`, нумерація з 1001 задається `ALTER SEQUENCE "support_requests_number_seq" RESTART WITH 1001` у третій міграції.
3. **Локаль бази.** З локаллю `C` PostgreSQL не переводить кирилицю в нижній регістр, і пошук учасника «олег» в адмінці не знаходив «Олег». Вимогу описано в `docs/RUNBOOK.md`; у `docker-compose.yml` і CI база створюється з `--locale-provider=builtin --builtin-locale=C.UTF-8`; API під час старту пише помилку в лог, якщо локаль не знає регістр кирилиці.
4. **Тест сусідніх номерів чеків** очікував, що чек, який оцінюється, входить у власних сусідів. Запит правильно його виключає; тест виправлено і доповнено.
5. **Закінчення рядків.** 23 файли мали CRLF; повернуто LF відповідно до `.gitattributes`.

## Як відтворити локально без Docker

```bash
# 1. Розпакувати postgresql-17.x-windows-x64-binaries.zip, далі з теки pgsql/bin:
initdb -D pgdata -U postgres -A trust -E UTF8 --locale-provider=builtin --builtin-locale=C.UTF-8
pg_ctl -D pgdata -l pg.log -o "-p 54329 -c listen_addresses=127.0.0.1" -w start
psql -h 127.0.0.1 -p 54329 -U postgres -c "create database portcity_test;"

# 2. У теці backend:
export DATABASE_URL="postgresql://postgres@127.0.0.1:54329/portcity_test?schema=public"
npm ci && npm run db:generate
npx prisma migrate deploy
npm run db:seed
npm run test:int && npm run test:e2e

# 3. Зупинити сервер
pg_ctl -D pgdata -w stop
```
